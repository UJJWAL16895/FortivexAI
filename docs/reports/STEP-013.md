# STEP-013 · Reliability

Before, the socket learned about a disconnect after finishing its current reply. A bounded receiver now watches while the reply runs, and the task group closes the provider iterator when the browser disconnects. A slow model reaches a deadline and falls back before visible output. The server log filter masks tested email and phone forms, including Devanagari digits. Existing tests cover both STT fallback directions and duplicate confirmation. Cancellation of saved bookings is deferred to the optional transactional booking pass.

## Quiz

1. **Who watches for disconnects?** The socket receiver.
2. **Who closes the partial stream?** The task group cancels the handler, and aclosing cleans up the iterator.
3. **How does a slow model fail safely?** A deadline produces a fallback event, then the next provider can answer.
4. **What keeps confirmations from creating two bookings?** The unique SQLite slot.
5. **What data is covered by testing the log filter?** Email and phone patterns, including decimal Unicode phone digits.
